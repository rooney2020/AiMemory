# AI Memory Qt 原型用户流程

## 版本说明

- 当前主线风格：暗色专业情报台
- 保留对照稿：科技清爽情报台
- 目标：把会话、记忆、图谱、资产、反馈观察放进连续工作流

## 流程 1：总览进入会话调查

### 路径

1. 用户进入总览页。
2. 在“当前关注的记忆与证据”中看到高优先级问题。
3. 点击“进入会话页”或直接点击某条证据卡。
4. 进入会话记录页后，左侧列表已按真实更新时间排序。
5. 中间 transcript 区查看 assistant / user / 关键动作的因果顺序。
6. 右侧调查面板查看结论、规则和下一步动作。

### 设计目的

- 减少用户先切页面再定位内容的跳转成本。
- 让“问题定位”成为总览页的自然下一步，而不是重新搜索。

## 流程 2：从会话沉淀为记忆

### 路径

1. 用户在会话记录页确认问题链路。
2. 点击侧栏中的规则或结论入口。
3. 跳到记忆详情页。
4. 在中间编辑区查看摘要、正文、强度和关联上下文。
5. 在右侧元信息面板决定是否复制引用、追加标签、生成摘要。

### 设计目的

- 把“看会话”与“沉淀记忆”连接起来。
- 避免会话证据和最终记忆脱节。

## 流程 3：从记忆进入资产工位

### 路径

1. 用户在记忆详情页发现某条规则已经形成稳定方法。
2. 通过动作区跳到资产页。
3. 在资产工位查看它对应的原型文件、说明文档或交互规范。
4. 决定是否导出、复用或继续迭代。

### 设计目的

- 把抽象结论变成可复用产物。
- 让资产不只是文件路径，而是带来源和用途的工作单元。

## 流程 4：从会话或记忆进入图谱

### 路径

1. 用户在会话页或记忆页看到关键实体，例如 interactive_feedback。
2. 点击关联入口进入图谱页。
3. 在图谱中查看与解析器、会话页、排序策略、资产工位的关系。
4. 通过节点侧栏再次跳回对应会话或记忆。

### 设计目的

- 图谱不再只是展示关系，而是承担导航和调查作用。
- 提高复杂问题排查时的上下文连贯性。

## 流程 5：风格选择与原型对照

### 路径

1. 用户打开 style-preview.html。
2. 在同一页面里查看当前主线风格与保留对照稿。
3. 比较配色、排版、信息密度和阅读舒适度。
4. 决定后续继续迭代的主线风格。

### 设计目的

- 降低“只靠语言描述风格”的沟通损耗。
- 为后续增加更多风格分支预留比较入口。

## 流程 6：长时挂机观察 feedback 链路

### 路径

1. AI 发起单一 feedback。
2. 用户挂机，feedback 窗口保持开启并按设定自动回复。
3. 系统记录 AI 发起时间、用户回复时间、工具返回时间。
4. 若出现断开，按反馈观察说明中的判定表归因。
5. 形成最终结论：用户主动结束、连接层问题、超时机制或 feedback 状态管理错误。

### 设计目的

- 不再只看表面现象“断开了”。
- 通过完整链路定位到底是谁的问题。

## 关键状态覆盖

### 加载态

- 刷新工作台时，按钮进入忙碌态。
- 局部区域可出现轻量骨架效果。
- 完成后统一用 Toast 提示。

### 空状态

- 搜索无结果时给推荐维度。
- 图谱无节点时给生成入口。
- 资产无内容时给导入或创建入口。

### 错误态

- 会话链路异常时，应展示“当前判断 + 证据不足点 + 下一步动作”。
- feedback 异常时，应区分用户主动结束、连接断开、超时和重复调用。

## 当前建议的评审顺序

1. 先看 style-preview.html，确认暗色专业方向是否成立。
2. 再看 dark-professional.html，重点评审总览页和会话页。
3. 最后结合 feedback-monitoring.md，确认挂机观察链路是否满足排查要求。
